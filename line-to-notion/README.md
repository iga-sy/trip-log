# line-to-notion

LINE公式アカウント（Bot）宛に1:1チャットで送ったテキスト・写真を、自動でNotionのデータベースに追加するWebhookサーバー。Vercel Functions上で動作する。判定・抽出はすべて文字列処理のみで行い、Claude APIなどの有料AI機能は一切使用しない（完全無料で運用できる構成）。

`那須旅行_202409/trip-diary/` とは独立したプロジェクト（依存関係・デプロイ設定は別）。

## 仕組み

1. LINE公式アカウントにメッセージ・写真を送る
2. LINEプラットフォームが `api/webhook.ts` にWebhookを送信
3. `x-line-signature` ヘッダーで送信元を検証（Channel Secretを使ったHMAC-SHA256）
4. テキストはそのまま、画像はLINE Content APIから取得しNotion File Upload APIでアップロード
5. メッセージ本文の1行目が「予定」であれば「予定」データベースへ、そうでなければ「全体感想」データベースへ新規行として追加（判定ロジックは下記「予定フォーマット」参照）

同一Webhookリクエスト内（`events`配列）にまとまっている同一ユーザーのイベントは1行にまとめる。リクエストをまたぐ場合はまとめず別行になる（外部の状態保存を持たないため）。

過去にLINEで送信済みのメッセージは取得できない。今後の投稿のみが対象。

対象は1:1チャットのみ。グループトークでの発言は無視する。

## 予定フォーマット

メッセージの1行目が「予定」という文字列そのものであれば、以降の行を `ラベル: 値` として解析し、「予定」データベースに新規行を作成する。食べログ等のページ情報をそのままコピペしても使えるよう設計している。

```
予定
タイトル：Pino cafe&meal
日時：2025/4/29 11:26
リンク：ピノ カフェ&ミール
0287-74-5726
栃木県那須郡那須町高久甲5109-10
https://tabelog.com/tochigi/A0905/A090501/9017730/
```

複数の旅行が並行しているときだけ、「旅行：」ラベルで対象を明示できる。

```
予定
旅行：京都旅行2025
タイトル：清水寺
日時：2025-05-01 10:00
```

- ラベルは「タイトル」「日時」「旅行」の3種類（全角・半角コロン両対応、順不同。これはLINEメッセージ上のラベルであり、Notion側の列名とは別物）。「旅行」は省略可能（下記「複数の旅行を扱う」参照）
- 「日時」は `YYYY-MM-DD HH:mm` 、`YYYY/MM/DD HH:mm` など区切り文字（ハイフン/スラッシュ）・月日時分の桁数（1桁/2桁）を問わないプレーンテキスト形式に対応
- **URLは「リンク：」ラベルの値ではなく、メッセージ全体から `http(s)://` で始まる文字列を自動検出する。** 食べログ等のコピペでは店名やURLがラベル通りの位置に来ないことが多いため、ラベルの位置に関わらずURLらしき文字列を拾う
- **「タイトル」と「日時」の両方が揃って初めて「予定」として作成される。** どちらか欠けている、または日時の形式が不正な場合は、安全側としてメッセージ全文がそのまま「全体感想」データベースに投稿として保存される（予定は作られない）
- 抽出した「タイトル」は実際の「予定」データベースの**「スポット名」**列に、自動検出したURLは**「リンク」**列に書き込まれる（実際の列名は下記「Notion側の事前準備」参照）
- 「予定」データベースの**「旅行名」**列（タイトル型）には、「旅行：」ラベルで指定した旅行名（省略時は`ACTIVE_TRIP_NAME`の先頭）が書き込まれる（下記「複数の旅行を扱う」参照）
- 「予定」データベース側の「修」「美」「悠」「紗」の各列（コメント欄）はLINEからは書き込まれず、常に空欄で作成される。感想やコメントは、これまで通りNotion上でその予定を開いて各自が直接入力する

## 「全体感想」データベースの構成と名前プレフィックス

代表者がLINEで代筆する運用のため、LINEの表示名は投稿者の判別に使えない。そこで、本文の先頭に家族の名前（修/美/悠/紗）とコロンを付けてもらうことで、誰のコメントかを判定する。

```
修: 今日のカピバラかわいかった
```

複数の旅行が並行しているときだけ、本文の先頭に`[旅行名]`を付けて対象を明示できる。

```
[京都旅行2025] 修: 清水寺きれいだった
```

- 先頭が「修:」「美:」「紗:」「悠:」（全角・半角コロン両対応）であれば、その名前を「マルチセレクト」列に設定し、プレフィックスを除いた本文を「メモ」列に保存する
- 名前プレフィックスが無ければ、「マルチセレクト」列は空のまま、本文全体を「メモ」列に保存する（誰かは分からないが記録は残る）
- 「投稿者」列（タイトル型）には、`[旅行名]`プレフィックスで指定した旅行名（省略時は`ACTIVE_TRIP_NAME`の先頭）が書き込まれる（下記「複数の旅行を扱う」参照）
- 写真は「写真」列（ファイル&メディア型）に添付する

## 複数の旅行を扱う

「予定」「全体感想」の両データベースはDBを分けず単一のまま、行ごとにタイトル型プロパティ（「旅行名」「投稿者」）へ旅行名を入れて区別する方式を採る。

- 環境変数`ACTIVE_TRIP_NAME`はカンマ区切りで複数の旅行名を指定できる（例: `那須旅行2024,京都旅行2025`）。**先頭がデフォルトの旅行**になる
- 通常はメッセージに何も書かなければ、自動的に先頭（メインの旅行）として記録される
- 別の旅行として記録したいときだけ、「予定」メッセージには「旅行：」ラベルを、「全体感想」メッセージには本文先頭の`[旅行名]`を付ける（`ACTIVE_TRIP_NAME`のリストに含まれているかはチェックしないため、自由なタイミングで新しい旅行名を書き始めてよい）
- 次の旅行がメインになったら、Vercel Dashboardで`ACTIVE_TRIP_NAME`の並び順を書き換えて再デプロイ（またはRedeploy）する。Notion側でデータベースを新規作成する必要はない
- `trip-diary`側は「予定」「全体感想」の各行を旅行名でグルーピングしてタブ表示するため、Notion側で旅行名さえ正しく入っていれば自動的に新しい旅行のタブが増える

## Notion側の事前準備

1. 「全体感想」データベースに、以下の列がある状態にする
   - タイトル型プロパティ（列名は何でもよい。今回は空のまま使う）
   - マルチセレクト型プロパティ「マルチセレクト」（選択肢に「修」「美」「悠」「紗」を用意）
   - テキスト型プロパティ「メモ」
   - ファイル&メディア型プロパティ「写真」
2. 「予定」データベースは、以下の列名になっている（`trip-diary`の`fetch-notion.ts`とプロパティ名を一致させる必要がある）
   - タイトル型プロパティ「スポット名」（実際にお店・施設名が入る列。同じDB内のタイトル型プロパティ「旅行名」は今回は使わない）
   - 日付型プロパティ「日時」
   - URL型プロパティ「リンク」
   - ファイル&メディア型プロパティ「写真」
   - テキスト型プロパティ「修」「美」「悠」「紗」（コメント欄、LINEからは書き込まない）
3. Notion Integrationを新規発行し、「Insert content」権限を付与
4. **「全体感想」データベースと「予定」データベースの両方**をそのIntegrationと接続（各データベースページ右上「•••」→「コネクト」）

## 環境変数

`.env.example` を参照。ローカル開発時は `.env` を作成（`.gitignore`済み）。本番はVercel Dashboard → Project Settings → Environment Variables に設定する。

| 変数名 | 取得元 |
|---|---|
| `LINE_CHANNEL_SECRET` | LINE Developersコンソール（Messaging APIチャネルの基本設定） |
| `LINE_CHANNEL_ACCESS_TOKEN` | LINE Developersコンソール（長期トークン発行） |
| `NOTION_API_KEY` | Notion Integrations（上記で新規発行したもの。trip-diary用の読み取り専用キーとは別にする） |
| `NOTION_COMMENTS_DATABASE_ID` | 「全体感想」データベースのURLに含まれるID（trip-diaryの`.env`と同じ値） |
| `NOTION_DATABASE_ID` | 「予定」データベースのURLに含まれるID（trip-diaryの`.env`と同じ値） |
| `ACTIVE_TRIP_NAME` | 現在進行中の旅行名（カンマ区切りで複数可、先頭がデフォルト。詳細は「複数の旅行を扱う」参照） |

## LINE公式アカウントのセットアップ

1. LINE Official Account Managerで公式アカウントを作成
2. 「Messaging API」を有効化（LINE Developersコンソールにチャネルが自動反映される）
3. LINE Official Account Manager側「応答設定」で「応答メッセージ」をOFFにする（Webhookのみで処理するため）
4. LINE Developersコンソールの「Messaging API設定」タブで「Webhookの利用」をON
5. Channel Secret・Channel Access Token（長期）を発行して控える
6. デプロイ後、Webhook URLに `https://<デプロイ先ドメイン>/api/webhook` を設定し「検証」ボタンで200が返ることを確認

## ローカル開発

```bash
npm install
npm test         # 単体テスト（署名検証・予定フォーマット判定・プロパティ組み立てロジック。外部通信なし）
npm run typecheck
```

実機Webhookのローカル検証には `vercel dev` ＋ ngrok等のトンネリングツールが必要（LINEプラットフォームからローカル環境に到達させるため）。

## デプロイ

VercelでこのGitHubリポジトリを連携し、**Root Directoryを `line-to-notion` に設定**してインポートする。`vercel.json`は不要（`api/`ディレクトリ規約と Web Standard `fetch` エクスポート形式で自動認識される）。mainブランチへのpushで自動デプロイされる。

## 制約・既知の注意点

- Notion File Upload APIでアップロードしたファイルは、**1時間以内にページへ紐付けないと失効する**（本実装は取得後すぐ紐付けるため通常は問題にならない）
- 無料（Hobby）ワークスペースはNotionファイル1つあたり5MiBまで
- Notion書き込み失敗時はログのみでLINE側には常に200を返す（LINEプラットフォームは非200が続くとWebhookを無効化しうるため）
- LINEのWebhook再送により、同一メッセージが重複してNotionに書き込まれる可能性がある（重複排除は実装していない。手動削除で対応）
