# 旅行のしおり（trip-diary）

家族でNotionに入力した旅程・メモ・写真・コメントをもとに、1ページの旅行記録・しおりサイトを自動生成してGitHub Pagesに公開する。合言葉（パスワード）を知っている家族だけがコンテンツを見られる。

左に写真ギャラリー（固定表示）、右に旅程タイムライン（スクロール表示、コメントは各予定の右側に表示）を並べる2カラムレイアウト（スマホでは縦積み）。各予定には食べログ/店HPへのリンクと、家族それぞれのコメントを添えられる。ページ下部には旅全体への感想、一番下には訪問地点をまとめた地図を表示する。

## 仕組み

1. 家族がNotionの**2つのデータベース**（予定用・全体感想用）に入力する（下記スキーマ参照）
2. GitHub Actionsが定期実行（毎日朝6時JST）または手動実行でNotion APIからデータを取得
3. 写真をダウンロードして静的アセット化。各予定の「タイトル」（お店・場所の名前）をそのままOpenStreetMapの無料ジオコーディングAPI(Nominatim)に問い合わせて座標を取得（地図用URLの入力は不要）
4. 取得したデータ全体を`SITE_PASSWORD`を鍵にAES暗号化し、`public/data.json`として書き出す
5. 静的サイトとしてビルドし、GitHub Pagesにデプロイ
6. 家族はURLを開き合言葉を入力するとブラウザ側で復号され、しおりが表示される

Notion APIキー・`SITE_PASSWORD`はGitHub Actions上でのみ使用され、ビルド成果物やソースコードに平文で残ることはない。

### セキュリティ上の注意（重要）

これは**強固なアクセス制御ではない**。静的ホスティングという制約上、暗号文（`public/data.json`）と復号ロジック（JSの中身）は認証前から全員のブラウザに配信される。つまり：

- ブラウザの開発者ツールで暗号文と復号処理を見ることができる第三者は、サーバー側のレート制限が存在しないため、オフラインで無制限にパスワードを試行できる
- 短い単語や辞書に載っているような合言葉は避け、ある程度長く推測しにくい合言葉を設定すること
- `public/images/`配下の写真ファイル自体は暗号化されていない。ファイル名はNotionページID（推測困難なUUID）由来のため検索エンジンや総当たりでは見つかりにくいが、URLを直接知っている第三者には合言葉なしで閲覧できてしまう

「検索エンジンに載らない」「URLを偶然踏んだだけの人には見せない」程度の目隠しとして使うことを想定している。本当に見せたくない人がいる場合の防御手段ではない。

## Notionデータベースのスキーマ

Notionに**2つのデータベース**を作成する。どちらも同じインテグレーションと共有すること。

### 1. 予定データベース（メイン）

以下のプロパティ名で作成する（`scripts/fetch-notion.ts`の`PROPERTY_NAMES`と一致させること）。

| プロパティ名 | 型 | 用途 |
|---|---|---|
| タイトル | タイトル | 予定・場所の名前（必須。無くても動くが「(無題)」になる） |
| 日時 | 日付 | タイムライン順ソート用（必須。未入力の行はサイトに出ない） |
| メモ | テキスト | 現地メモ・感想（任意。家族共通の自由記述欄） |
| お店リンク | URL | 食べログや店のHPなどのリンク（任意。入れておくとタイムラインの店名がそのままリンクになる） |
| 写真 | ファイル&メディア | 現地で撮った写真（任意。**その行に直接アップロード**する。1行＝1つの予定で、その行の写真プロパティがそのままその予定の下に表示される。他の行の写真と紐付ける処理は無いので、場所名をメモに書いて後から照合する必要はない） |
| コメント(修) | テキスト | 「修」さんのその予定へのコメント（任意） |
| コメント(美) | テキスト | 「美」さんのその予定へのコメント（任意） |
| コメント(悠) | テキスト | 「悠」さんのその予定へのコメント（任意） |
| コメント(紗) | テキスト | 「紗」さんのその予定へのコメント（任意） |

データベースの「タイトル」（データベース自体の名前）がサイトの旅行タイトルとして使われる。

家族の呼び方（修・美・悠・紗）を変える場合は、`scripts/fetch-notion.ts`の`FAMILY_MEMBERS`配列とNotion側の列名を両方合わせて変更すること。

### 2. 全体感想データベース（サブ）

旅全体（お店ごとではなく）への感想を集める、シンプルな2列だけのデータベース。誰でも好きなだけ行を追加してよい。

| プロパティ名 | 型 | 用途 |
|---|---|---|
| 投稿者 | セレクト | 選択肢に「修」「美」「悠」「紗」を用意しておく |
| コメント | テキスト | 感想本文 |

並び順はNotionの作成日時（自動）を使うため、日付プロパティは不要。

### 地図について

ページ最下部の「地図」セクションは、座標を取得できた予定をすべて1枚のOpenStreetMap上にピン表示する。**専用の位置情報プロパティは無く**、各予定の「タイトル」（お店・場所の名前）をそのままNominatim（OpenStreetMapの無料ジオコーディングAPI）に問い合わせて座標を求める。

- Nominatimの利用規約により1リクエストあたり1秒以上間隔を空けるため、予定の件数が多いとビルドが少し遅くなる
- 同名の店が全国に複数ある場合など、意図しない場所にピンが立つことがある。その場合は`scripts/lib/geocode.ts`のクエリにエリア名を補うなど調整が必要
- 座標が見つからなかった予定にはピンが立たないが、タイムライン上の表示自体には影響しない

## ローカル開発手順

1. Notionで内部インテグレーションを作成し、APIキーを取得
2. 上記の2つのデータベースをそのインテグレーションと共有（各データベースページ右上の「…」→「接続の追加」）
3. `.env.example` を `.env` にコピーし、`NOTION_API_KEY` / `NOTION_DATABASE_ID` / `NOTION_COMMENTS_DATABASE_ID` / `SITE_PASSWORD` を設定
4. 依存関係をインストール

   ```bash
   npm install
   ```

5. Notionからデータを取得・暗号化（初回は必須。実行しないと`public/data.json`が存在せず何を入力しても開けない）

   ```bash
   npm run fetch-notion
   ```

6. 開発サーバー起動

   ```bash
   npm run dev
   ```

   ブラウザで`.env`に設定した`SITE_PASSWORD`を入力するとしおりが表示される。

npm run build

## GitHub Pagesへの公開手順（初回のみ）

1. GitHubに新規リポジトリを作成し、このフォルダをpush
2. リポジトリの `Settings → Secrets and variables → Actions` に `NOTION_API_KEY` ・ `NOTION_DATABASE_ID` ・ `NOTION_COMMENTS_DATABASE_ID` ・ `SITE_PASSWORD` を登録
3. `Settings → Pages → Source` を「GitHub Actions」に設定
4. `Actions` タブから `Deploy Trip Diary to GitHub Pages` を手動実行（`workflow_dispatch`）して公開を確認

以降は `main` へのpush・毎日の定期実行・手動実行のいずれかでNotionの最新内容が反映される。合言葉を家族に伝える際はURLとは別の経路（口頭やメッセージアプリ）で共有する。

60日間pushが無いとGitHubの仕様で`schedule`トリガーが自動停止するため、更新が滞っている場合は`Actions`タブから手動実行して復旧する。

`SITE_PASSWORD`を変更した場合は、次回のビルド（手動実行でよい）以降のみ新しい合言葉が有効になる。変更前にアクセスした端末には`sessionStorage`に旧パスワードがタブを閉じるまで残るが、再取得時に復号失敗として扱われ再入力を求められる。
